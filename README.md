# Parallax

A simulated economy where financial agents investigate bank shocks, negotiate credit, and compare rescue policies.

![tag:innovationlab](https://img.shields.io/badge/innovationlab-3D8BD3)
![tag:hackathon](https://img.shields.io/badge/hackathon-5F43F1)

Parallax turns a financial stress test into an interactive investigation workspace. Start with households, businesses, and banks, introduce a hypothetical bank investment loss, and follow the effects on credit, payroll, production, and defaults. Compare three possible futures before deciding whether to apply support.

The first intended audience is finance learners and instructors exploring how bank shocks affect business credit and jobs. This is an audience hypothesis awaiting user validation. Parallax uses synthetic bank and business finances, so this task requires no private bank data. It is an investigation prototype, not a forecast or a service for making real lending decisions.

## What you can do

- See percentage changes in employment, cash, bank stress and defaults; select banks and businesses to inspect their finances.
- Introduce a bank investment loss and advance the economy to see its calculated consequences, including the branch's gradual-layoff model.
- Use **Fork Reality** to compare no intervention, emergency bank lending, and direct household support from the same saved starting state.
- Watch an investigator hand evidence to a policy planner, inspect the actual exchanged data, and read an independent supervisor review. Applying support is a separate action, blocked if the required review has not passed.
- Let business and bank agents negotiate payroll credit. Review uncertain evidence or large offers before separately confirming settlement.
- Negotiate supplier purchases, review payment terms, and watch inventory affect production and sales.
- Coordinate a proposed bank shock across two browsers through a shared SpacetimeDB control room.
- Download a comparison report containing calculated outcomes, assumptions, and source provenance.

## Geography and alternate worlds

The financial model is a generic simulated economy. San Francisco supplies limited optional menu-price and minimum-wage references and inspires the optional city illustration; it does not define the simulated banks, population or financial network. Alternate worlds compare different bank investment losses from one saved starting state, separately from rescue-policy comparisons. New economies retain their original snapshot; existing economies without one use an explicitly labeled current-state snapshot.

## What is real, and what is simulated?

**Public observations:** our custom Apify Actor collects posted drink prices from one San Francisco cafe and the official general minimum wage. The app loads saved inputs automatically and refreshes missing or stale data with bounded runs when Apify is configured. New worlds use and freeze their selected sample and provenance. One cafe's menu is not a citywide price index, and the minimum wage is a legal floor, not average earnings. The app explicitly assumes eight hours when converting the hourly wage to a daily reference.

**Simulated state:** households, financial balances, bank portfolios, employment relationships, production, and behavior are generated by the model. The default world contains 40 households, 8 businesses, and 5 banks. Baseline unemployment and gradual layoffs are model assumptions, not live labor-market measurements. The city is a stylized visualization; extra scenery inspectors are illustrative profiles rather than backend financial institutions.

**Hypothetical scenarios:** a bank asset loss is an input to an experiment. The optional Treasury story retrieves dated national debt and lets a user choose separate hypothetical debt, yield, and exposure assumptions. It does not predict wars, infer a causal debt-to-yield relationship, or forecast the national economy.

**AI:** live agents use NVIDIA Nemotron through Nebius. Tools obtain facts and calculate outcomes; models propose actions and explain evidence. Explicit deterministic demo mode is available. Live-provider failures are reported rather than silently replaced with a successful AI result.

## Run locally

Use Python 3.11+ and Node.js 22. Run these commands from the repository root. The integrated code is published on **main** in the Econova repository.

```powershell
git clone https://github.com/shivanginarayan/Econova.git
cd Econova
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
npm ci
```

If you need live integrations, create a private `.env` using [.env.example](./.env.example) as a template. Preserve an existing configuration. The backend launcher loads supported settings; no provider keys belong in frontend code.

Start the API:

```powershell
.\.venv\Scripts\python.exe -m scripts.run_backend --port 8000
```

Start the web app in a second terminal:

```powershell
npm run dev
```

Open **http://127.0.0.1:5173**. The development server forwards API requests to port 8000; API documentation is at **http://127.0.0.1:8000/docs**. If that frontend port is occupied, use the URL printed by Vite.

On macOS/Linux, use `.venv/bin/python` instead of `.\.venv\Scripts\python.exe`. The simulation and deterministic agents require no API key. Without configured public-input access, explicitly choose **Seeded synthetic inputs** when creating a world; live sponsor services need their own configuration. Saved worlds and private integration state live under ignored `data/`.

### Optional integration setup

- **Live financial agents:** set `NEBIUS_API_KEY`, `NEBIUS_MODEL`, and optionally `NEBIUS_BASE_URL`. The verified model is `nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B`. See [Nemotron setup](./docs/NEMOTRON.md).
- **Automatic public inputs:** set `APIFY_TOKEN` and `APIFY_ACTOR_ID`. Use our published Actor or deploy the included collector. See [Apify setup and collection limits](./docs/APIFY.md).
- **CRS underwriting:** configure sandbox login or an access token, the enabled credit product, sponsor-only test profiles, and documented score/risk mappings. Account-specific files are private and are not distributed with the repository. See [credit setup and live verification](./docs/TRACK_IMPLEMENTATION.md).
- **Fetch gateway:** configure a private stable agent seed and Agentverse access, then run the gateway separately. See [Fetch setup](./docs/FETCH_AGENT.md). The optional ASI inference key is distinct from the registered gateway integration.
- **Shared control room:** run/configure SpacetimeDB and publish its module using the documented identity and permissions. See [Spacetime setup and demo](./docs/SPACETIME_SUBMISSION.md).
- **Paid research:** uses a separate merchant, isolated x402 environment, and Base Sepolia test wallet. See [payment setup](./docs/SPONSOR_INTEGRATIONS.md) and [verified x402 evidence](./docs/X402_SUBMISSION.md). Do not rerun the durable payment verifier just to reproduce an existing receipt.

Optional services are separate from the two-process basic app. A public repository does not supply API credits, account credentials, a funded wallet, or a hosted backend.

## A short demo

1. Create a **Credit crunch** world. Show whether its inputs are public observations or an explicitly seeded sample.
2. Trigger a **40% loss on Bank 1's risky investments** while paused. This is not a 40% reduction of customer deposits.
3. Open **Fork Reality** and compare the three futures. Quote the actual displayed outcomes; interventions are not guaranteed to improve them.
4. Return to the city and test rescue policies in live agent mode. Show the tool evidence and explanation, then the separate apply action.
5. Inspect a business for **Credit safeguards** or **Negotiate supplies**. For credit, use a world with a payroll shortfall. Show the review gate before any settlement.
6. Open **Sources & agents** for public-input provenance and sponsor controls. Use two browser sessions for the shared control-room demonstration.

Opening the app can restore a saved experiment. **Create World** starts a fresh one; reset also preserves prior history. Analysis uses a saved snapshot, and changing that source can invalidate an unexecuted proposal.

## How the financial core works

The backend calculates money in integer cents and records balanced accounting entries. Lending creates matching loan and deposit claims; repayment reverses them. Payments between banks move reserves. Source changes invalidate stale approvals, and repeated financial requests cannot silently execute the same action twice.

Forks start from the same saved source and controlled randomness. Their ranking is rule-based and separate from the AI explanation. Background jobs preserve public tool traces without publishing hidden model reasoning. SQLite stores the financial state, reports, events, and receipts.

The frontend uses React, TypeScript, Vite, and Zustand, with a financial investigation workspace and an optional stylized city view. The backend uses Python, FastAPI, and Pydantic. SpacetimeDB supports the shared room; uAgents/Agentverse supports the external agent interface.

## Model credibility and repeatable checks

New economies use versioned scheduled interbank settlement; existing snapshots keep their earlier assumptions. A bank investment loss is distinct from a household withdrawal run. The revised settlement retains a 10% deposit liquidity buffer at solvent banks, rather than treating all deposits as simultaneously payable. This buffer and par-value conversion of recorded risky assets are model assumptions, not claimed regulations or realistic market liquidation.

See [model evidence](docs/MODEL_CREDIBILITY.md) for the matched old/new comparison, frozen input identity, limitations and repeat commands. The evaluation retains all five seeds, four severities and three horizons, including equal outcomes and deteriorating no-shock controls. Accounting consistency and sensitivity are tested; empirical accuracy and customer usefulness remain unvalidated.
